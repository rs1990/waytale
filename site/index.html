Mobile and content pipeline

The narration is written before you arrive.

WayTale narrates the history, geography, and culture of landmarks as you travel. The design bet is that live generation is the wrong answer: facts are pulled from Wikidata and Wikipedia, drafted into scripts by Claude, synthesized to audio once, reviewed by a human, and cached. Every user hears the same approved recording.

What it does

Pre-generation is the architecture, not an optimization.

Generating narration at request time would mean paying for every listen, waiting for every listen, and shipping unreviewed claims about real places to real people. WayTale inverts that. An offline pipeline pulls landmark metadata from Wikidata SPARQL and sourced text from the Wikipedia REST API, drafts four script variants with Claude constrained to those facts, synthesizes audio through Amazon Polly, and lands rows in Postgres with status pending.

An admin dashboard is where content becomes real. A reviewer reads the script alongside its sources and approves, publishes, or rejects. The mobile app queries only rows with status published, so nothing reaches a user that a human has not signed off on. Every fact carries a provenance tag of verified, legend, or mixed, enforced at the schema level and surfaced as a badge in the interface, so folklore is never presented as history.

The backend is an Express service over PostGIS. Landmark locations live in a GEOGRAPHY(POINT, 4326) column with a GIST index, which makes nearest-landmark lookups a spatial query rather than a bounding box scan. The Expo app polls GPS, fetches nearby landmarks, and fires narration when the user crosses a 250 metre geofence.

Content does not go stale silently. A refresh log tracks the Wikipedia revision each script was drafted from, so a redraft only fires when the source article actually changed, and the previously published version stays live until the new one clears review.

Engineering details

The decisions that carry the design.

01

Publish-gated cache

The application reads only rows with status published. Pipeline output is fully insulated from users until a reviewer approves it, which means a bad draft is an internal problem rather than an incident.

02

PostGIS spatial queries

Landmark locations use a GEOGRAPHY(POINT, 4326) column with a GIST index, so nearest-landmark lookups are true spatial queries rather than bounding box approximations.

03

Revision-diffed refresh

A content refresh log records the Wikipedia revision behind each script. Redrafts fire only when the source article changed, and the live published version is never pulled down while its replacement is in review.

04

Schema-level fact provenance

Every piece of content is tagged verified, legend, or mixed. The constraint lives in the database, not in application code, and the tag is rendered as a visible badge.

05

Source citations throughout

Each narrated fact links back to its Wikipedia or Wikidata origin, so a listener can check any claim rather than trust the app.

06

Route scoring

The backend returns two or three route options scored on travel time, landmark count, and a crowd heuristic, built over a raw latitude and longitude route endpoint.

07

Multi-day itinerary builder

Place-name search and itinerary assembly sit on top of the same scoring endpoint, letting a trip be planned across days rather than a single drive.

08

Reproducible local stack

Docker Compose brings up Postgres with PostGIS, the backend, and the admin dashboard together. The PostGIS image is pinned to linux/amd64 through Rosetta after the arm64 manifest proved unavailable for the pinned tag.

Status

An honest account of what is built and what is not.

Backend, content pipeline, and admin dashboard are functional locally through Docker Compose and a launch script, with content seeded for all 63 US National Parks.

Built in a concentrated sprint of 14 commits across roughly 30 hours, which included fixing two check-constraint bugs and a SPARQL latitude and longitude extraction bug along the way.

Not built, and listed as roadmap rather than implied: offline itinerary downloads, interest-based personalization, live geofence auto-pause, subscription tiers, and multi-language support. There is no automated test suite in the repository.
